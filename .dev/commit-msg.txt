Add optional per-user two-factor authentication and a dormant transactional-email channel.

Two-factor is now available but never forced: a new `src/utils/mfa.js` wraps Supabase Auth's TOTP primitives — list factors, find the verified one, tell whether a password sign-in still needs a code to reach AAL2, enrol a new factor, create a challenge, verify a six-digit code and unenroll a factor — so the Settings page and the Login flow share one definition of the state. On Settings a new "Two-factor authentication" card shows whether it is on for the signed-in user, and turning it on walks through scanning a QR code (or typing the manual key), entering the six digits from Google Authenticator, Authy or 1Password to prove the device, and only then marks the factor verified; turning it off removes the factor outright. On Login, a password sign-in that lands at AAL1 with a verified factor present stops on a second step asking for the current six-digit code, a wrong code is re-challenged rather than dead-ending, and anyone without a factor signs in exactly as before — so no employee is locked out by someone else's setting. The code field is numeric-only, auto-focused and one-time-code aware so phones offer the code straight from the notification. Email is wired but deliberately dormant: `supabase/functions/send-email/index.ts` sends through Resend's REST API with the caller required to be signed in, the recipient restricted to a single address inside a configured domain so it can never become an open relay, length caps on subject and body, and a configuration probe that reports whether a key is present; every call while the `RESEND_API_KEY` secret is unset answers 503 `email_disabled` with the exact `supabase secrets set` command to run, so shipping now changes nothing until the operator pastes a key. Verified: `npm run build` green with bundle `index-vEFVpeIY.js` and CSS `index-CdF5Z-lw.css`, i18n parity 1042/1042 in English and Arabic, `node --test .dev/unit_tests.mjs` 29/29 passing, `audit_mobile_v2.py` 0 clipped / 0 escapees / 0 small / 0 page overflow across every page at 360/390/414/768/1024 plus RTL, `drill_round1.py` 0 fails, `drill_consultations.py` 0 fails, and the Supabase Auth factors endpoint confirmed live (401 unauthenticated rather than 404).
